## 18. The lease's own notice and early-cancellation terms — captured, editable per lease, defaulted from the agency, shared with the lease agreement and the portal (8 Oct 2026, cc1 — Johan's ruling; QA1 only)

**Ruling (Johan, 8 Oct 2026, verbatim):** "based on the signed lease we show when notice can be given - contract states this and we have it from lease."

### 18.1 Where notice terms could come from before this (the report asked for first)
* **Lease capture form:** only `earliest_termination_date` ("earliest date notice may expire", registry row 16), and only when the agency's linked agreement carries it (`LeaseCaptureService::agreementFields`, `config/lease-agreement-fields.php`). Nothing for the notice length or early cancellation.
* **Lease e-sign template merge fields:** the agency's own field map links registry keys to template fields; the only notice-related key was `earliest_termination_date` (`RentalLeaseTemplateController::SUGGESTION_HINTS`); the HFC reference map (§15.12.5 #16) uses the single `notice_date`. No clause for length, early cancellation or penalty.
* **Agency rental settings:** `lease_settings.tenant_notice_period_days` (nullable, reads 30) and `expiry_notice_window_days` — settings, never copied onto a lease.
* **Lease record:** `notice_date / notice_given_by / move_out_date` record notice already GIVEN (not terms).
* **QA1:** 0 of 27 leases carried an earliest termination date; none carried a notice length or early-cancellation answer.

### 18.2 Data
`lease_agreement_terms` (one row per lease, migration `2026_10_18_000100`) gains `notice_period` (smallint) + `notice_period_unit` (`days|weeks|months`), `earliest_notice_date`, `early_cancellation_allowed` (`yes|no`, null = not on record), `early_cancellation_notice` + `early_cancellation_notice_unit`, `early_cancellation_penalty` (text) and `notice_terms_source` (`captured | edited | carried_forward | agency_default`). The existing `earliest_termination_date` stays where it is. The seven new keys are registry group **`notice`** (`config/lease-agreement-fields.php`; mappable and "required for signing" in the agency's field-map panel; `RentalLeaseTemplateController` suggests template fields by name).
**Agency defaults** (`lease_settings`, migration `2026_10_18_000200`; Settings → Leases and the Setup Wizard's Leases step, rule #10a): notice length (existing `tenant_notice_period_days`, default 30) + `tenant_notice_period_unit` (default days), `default_earliest_notice_months` (blank = no rule; otherwise the lease's earliest notice date = its start + N months), `default_early_cancellation_allowed` (default **yes** — see the business question in the build report), `default_early_cancellation_notice` + unit (blank = the same as the ordinary notice), `default_early_cancellation_penalty` (blank = none). Read-time defaults in `LeaseSetting`; nothing is hardcoded outside it. One class knows all of it: `App\Services\Rentals\LeaseNoticeTermsService` (fields, defaults, validation, audited save, renewal carry-forward, date arithmetic).

### 18.3 Where they are captured and edited
* **New lease and renewal capture screen:** an always-shown block "Notice and early cancellation" (linked agreement or not) pre-filled from the agency defaults, or — on a renewal — from the term being renewed with its dates moved by the same offset as the start date. A blank field takes the default at save; "No" early cancellation carries no notice or penalty; a length with no unit takes the agency's unit; the earliest dates may not precede the lease start (`LeaseCaptureRequest`). `earliest_termination_date` is shown in this block only when no linked agreement already asks for it. A renewal made any other way (`LeaseRenewalService::createRenewalTerm`, e.g. the renewal draft) carries the terms forward too.
* **Lease screen:** a "Notice terms" card (right panel): the terms in words, the dates worked out for that lease (earliest notice, notice-by for the end date, earliest end), "Filled from your agency defaults — check it against the signed lease" while the source is `agency_default`, "Changing these does not change the signed document" once signed. **Change / Set** → `PUT /leases/{lease}/notice-terms` (`corex.leases.notice-terms.update`), permission **`lease_notice_terms.edit`** (Role Manager; given to the branch-manager and agent defaults like `leases.create`), the usual own/branch/agency guard (another agency's lease is a 404), refused while the agreement is out for signing (same message as the edit panel).
* **Audit trail:** every save writes one `lease_notice_terms_changed` row to the tenancy log — who, which terms, from, to, when (`metadata.changes`); saving the same values again writes nothing; the capture records the starting terms and their source in the `lease_created` row (`metadata.notice_terms`); the back-fill writes `lease_notice_terms_backfilled`.

### 18.4 One value for the document and the portal
The seven keys are `terms`-side registry fields, so `LeaseAgreementDocumentValues` fills the lease agreement document from the same columns (when the agency's map carries them: `notice_period`, `notice_period_unit`, `earliest_notice_date`, `early_cancellation_allowed`, `early_cancellation_notice`, `…_unit`, `early_cancellation_penalty`), the document-vs-lease difference check and R6 confirm read and accept them like any agreement term, and the portal FAQ (`RentalPortalFaqService`) reads the same columns — the signed lease and the portal cannot disagree. A lease with none of its own terms still shows no FAQ, and neither does one whose terms no agent has confirmed (§18.7). Answers carry real dates for THAT lease: `{notice_from}` ("now" or "from 28 Dec 2026"), `{earliest_notice_date}`, `{notice_by_date}` (end date less the notice period, only while still ahead), `{earliest_termination_date}`, `{lease_end_date}`, `{notice_period}` ("2 months"), and the early-cancellation sentence built from the agency's own "allowed" / "not allowed" wording (agency settings `faq_{tenant|landlord}_cancel_{yes|no}`, `rental-portal-access.md` §22). The HFC reference map (§15.12.5) is HFC's own and was not edited; an agency whose agreement has fields for these maps them under Settings → Rental lease agreements.

### 18.5 Back-fill of existing leases — `php artisan leases:backfill-notice-terms`
Run by hand, never by a deploy: `--dry-run` first, `--agency=` / `--lease=` to limit, `--revert` to undo. Fills only an **active or draft** lease that holds none of its own notice terms (a lease with a notice period, earliest notice date or early-cancellation answer is never touched; archived, cancelled and expired are left), from ITS agency's defaults, tagged `agency_default`; never writes `earliest_termination_date`; writes through the query builder (no model events), logs `lease_notice_terms_backfilled` per lease (the values), prints counts per agency and examples. `--revert` clears exactly what it wrote, only while that is still what is there and no `lease_notice_terms_changed` has touched it since; running it twice changes nothing more.
**Honesty note:** a back-filled value is the agency's default, not read off the signed document — the lease screen says so until someone saves it.

### 18.6 Multi-agency (rule #9)
Defaults, wording and units are per agency; nothing names an agency; another agency's lease is a 404; the registry keys are neutral and reach a document only through that agency's own field map.

### 18.7 Nothing unconfirmed is ever shown to a tenant or owner — "confirmed" terms, the "to check" list, signed leases (8 Oct 2026, later; ruled by the conductor while Johan was away — Johan may overturn)
* **Confirmed.** `lease_agreement_terms.notice_terms_confirmed_at / _by` (migration `2026_10_18_000400`). Terms are confirmed when an agent **captures** them (new lease / renewal screen), **saves** them on the lease card (a save that changes something), or presses **Confirm terms** on the card (audited `lease_notice_terms_confirmed`: who, when). The back-fill and an agency-default fill are **never** confirmed; a renewal made without a screen carries confirmation only from a term that was confirmed. An edit that changes nothing does not confirm.
* **The portal.** `RentalPortalFaqService::forLease` returns no FAQ at all unless the lease's terms are confirmed — so nothing about notice, and nothing about early cancellation, is stated to a tenant or owner on agency-default terms. Early cancellation stays a per-agency default setting (new leases are pre-filled from it; the agent sees it before it is captured).
* **To-check list.** One definition, `Lease::scopeNoticeTermsUnconfirmed` (active or not; no confirmed terms row): the **lease list** filter *Notice terms → To check — not confirmed* (own/branch/agency through the list's own scope; printed/exported filter label) and the rentals command centre **needs-action queue** row *Confirm notice terms* (active leases only, own/branch/agency through the queue's property scope) which opens the lease. **Confirm terms** = `POST /leases/{lease}/notice-terms/confirm` (`corex.leases.notice-terms.confirm`), permission `lease_notice_terms.edit` (Role Manager), the usual own/branch/agency guard.
* **Back-fill revert** never clears terms an agent has since confirmed.
* **Signed lease.** Editing the terms of a lease whose agreement is signed (e-signed or on paper) **requires a reason** (validated, logged in `metadata.reason` and the history line); the card states the signed document is unchanged and an addendum is needed to change what it says. No silent edit.

### 18.8 The signed lease prints the terms (8 Oct 2026, later)
* **Shipped default lease agreement** (`docuperfect.web-templates.lease-agreement-popi-v8`): new clause **5.5** prints the seven terms as data-field spans (`notice_period`, `notice_period_unit`, `earliest_notice_date`, `early_cancellation_allowed`, `early_cancellation_notice`, `early_cancellation_notice_unit`, `early_cancellation_penalty`) — nothing prints when the lease holds none. The names equal the registry keys' suggestion hints, so *Map fields* auto-suggests them. Existing clauses (5.1 "40–80 business days", 16.4 "10% cancellation fee", 17.x) are **unchanged**; where an agency's recorded terms differ from them, that is a wording call for the owner of the template (flagged to Johan).
* **Merge-field picker** (the named-field catalogue, `docuperfect_named_fields`, migration `2026_10_18_000500`): seven computed rows "Lease Notice Period" … "Lease Early Cancellation Penalty", resolved by `WebTemplateDataService::resolveComputedFromKey`; in `WebTemplateFieldPartyMap` they are **system**-filled (not editable by a signer, so the document cannot differ from the lease record).
* **An agency's existing template** is the agency's own wording and is not edited by CoreX. To print the terms it needs, in *Settings → Rental lease agreements → Map fields*, the seven registry keys above mapped to whichever of its template fields hold them (or those fields added to its template first). HFC's mapping is reported in the build report.
