## 22. The same capture pressed twice is one lease (14 Oct 2026, QA1 - cc3's new-agency walk; tests in `LeaseCaptureTest`)

Cape walk: "Create lease & prepare for signing" made lease 135, the agent came back to the capture screen and pressed again - lease 136. The hidden `capture_key` (one per page load) only caught a double click on the same page. **Now (a) the capture screen ignores a second press while the first is being sent (and un-sticks if the browser restores the page from its cache), and (b) the server treats a lease made in the last 30 minutes for the same agency, property, start date, tenants (a renewal: the same lease being renewed) and the same outcome (lease only / prepare for signing / signed copy) as the same capture** - `LeaseCaptureService::recentTwin`. It returns that lease, writes no second "lease created" line, and the redirect says once "This lease was already created a moment ago - here it is. Nothing was created twice." Different tenants, start date, outcome, another agency's lease, an archived lease, or more than 30 minutes later are new leases. `DUPLICATE_WINDOW_MINUTES` is a constant; it is a guard, not an agency preference. The old test that allowed two identical drafts one after the other now allows them only when something differs.
