## 19. Front-half walk fixes (8 Oct 2026, cc3, QA1)
Walking "approved application -> lease -> signed -> active -> portal -> renewal" end to end found these hand-off gaps; each is fixed and pinned by a test (`LeaseActivationAndCaptureWalkTest`, `PortalHidesDraftLeasesTest`, `RentalFrontHalfEndToEndTest`):
* **Manual Activate follows the signing state.** A draft lease whose agreement is being prepared / out for signing / waiting for the agent's approval cannot be activated by hand (the button is not offered and the route refuses); a signed agreement that differs from its lease is sent to the confirm screen instead of being activated past it.
* **Activating a renewal draft by hand is a renewal activation** - escalation row, "renewal activated" history line, previous term expired and chained - the same bookkeeping the signing path does. The signing safety net (no acting user) records the escalation too (`created_by_user_id` null).
* **Confirm service only applies to a DRAFT lease** with an out / awaiting / signed agreement (UI and API twin): it can no longer rewrite an active lease's rent and dates from its document (`LeaseAgreementConfirmationRefused::NOT_APPLICABLE`).
* **Capture screen:** the same tenant twice is a validation error (was a unique-index 500); a linked `rental_application_id` must be one the user may see (same query as the screen), not merely one in the agency; Enter in a text field submits the default button (lease only / paper copy), never the hidden alternative.
* **A lease agreement is e-signed only:** the wizard hides, and the server refuses, the wet-ink and download-only delivery for a lease-launched flow (they never told the lease which envelope it became). A paper copy is captured on the lease screen ("I already have the signed copy").
* **Portal:** a DRAFT lease is invisible to the tenant and the owner (`RentalPortalScopeService::tenantLeaseIds` and the landlord lease queries); it appears once live. The sign-in code mail says "Enter this code to sign in" (the same mail serves the web portal).
