## 20. Front-half decisions (8 Oct 2026, cc3, QA1 - built while Johan was away)
Per-agency settings on `lease_settings` (nullable columns; NULL = the default below), audited in `rental_setting_audit`, saved by `LeaseSettingsController::update` (has()-guarded - also the wizard saver) and shown in the Setup Wizard Rentals step (rule 10a). Tests: `LeaseFrontHalfDecisionsTest`, `LeaseCaptureTest`. The application-side decisions are in `rental-applications.md` ("Front-half decisions").
* **D8 `require_end_or_month_to_month_for_signing` (on).** "Create lease & prepare for signing" (and prepare-again / the API) needs an end date, or month-to-month ticked, and lists it with the other gaps; nothing is created until it has one. "Create lease only" is never held to it.
* **D12 `restore_end_date_on_leaving_month_to_month` (on).** Both the agent's switch and the automatic one keep the end date they clear on the "month-to-month set" history line (`previous_end_date`); reversing puts it back when it is on record, **still ahead** and the lease has no end date now (a past date would send the lease straight back to month-to-month tonight). The restoration is logged. Switches made before this have nothing on record and are not touched.
* **D13 `signed_copy_not_live_note` (neutral default sentence; empty = say nothing).** The tenant / landlord signed-copy mail (`SignedDocumentMail`) carries it when the lease is still a draft and another lease is active on the property that is not its predecessor (`LeaseActivationService::blockingLease`, the same test `activate()` applies). The signed copy is always sent.
* **D11** (no setting): the portal sign-in code mail says "Use this code to sign in to your <agency> portal" when the person belongs to exactly one agency, a neutral line otherwise and for an unknown address (so it never hints whether an address is a client).
