## Agreement write-back (14 Oct 2026, Johan: "build it")
What an agent types into an agreement's **Fill & review** (lease or renewal - any e-sign agreement that pre-fills from the contact / property) and CoreX did not already know goes back onto the record the field pre-fills from, so every later document and renewal fills itself. `App\Services\Docuperfect\AgreementRecordWriteBack`; runs when Fill & review is saved with **Next** (`ESignWizardController::saveStep`, after the flow is saved - a failure never blocks the step).
- **Fields (the whole class).** Party (landlord/lessor, tenant/lessee, seller, buyer; 1st person, and a 2nd where the data service has a 2nd key such as `lessor2_address`; an expanded per-recipient `{id}__r{n}` field is the n-th person of its role): **address** -> `contacts.address`; **email** -> `contacts.email`; **phone** -> `contacts.phone`; **ID number** -> `contacts.id_number` (valid SA ID only, stamped `id_number_source = agreement_writeback`). Property: **erf** -> `erf_number` if that is the column in use, else `property_number` (the form's "Property / Erf Number" box, also used when both are empty); **complex name** -> `complex_name`; **unit** -> `unit_number` (the property's normal save recomposes its address and re-submits a live listing, exactly as an edit on the property page does). Full field-name list: `AgreementRecordWriteBack::FIELD_MAP`.
- **Never written:** names, bank details, street / suburb / town (a composed, portal-coded address), anything a document computes (money, dates, words), entities (they sign through representatives), anything for an assistant user, and a contact outside the user's agency (scoped lookup).
- **The rule.** A value is a candidate only when it is non-blank, different from the record, and different from what the pre-fill itself showed (a tenant's address CoreX took from their rental application is not "typed by the agent"). It is saved when the record's field is **empty - default on** - or when the agent ticks the inline **"Also update the landlord's record?"** (shown under the field only while the typed value is new; **default off** over a filled record, with "It currently says …"). The tick travels with the value it was made about (`{on, value}`): typing a different value starts again from the default. **Email, phone and ID are only ever filled, never replaced** (a contact's other numbers must not be lost, and an ID change is FICA-relevant) - no tick is offered for them over a filled record. An email / phone already held by another contact in the agency, an invalid email / ID, or a too-short number is skipped. Blank never overwrites.
- **Audit.** One `agreement_writeback` line on the contact (`contact_audit_logs`) or property (`property_audit_logs`): who, when, old -> new, "... saved from the agreement the agent filled in (e-sign flow #N) - the record had none / agent confirmed the change". The record's own observer audit row (field diff) is written as for any save.
- **Not a setting** (no agency toggle), so nothing for the Setup Wizard; the tick is the per-field choice. Tests: `tests/Feature/Docuperfect/AgreementRecordWriteBackTest.php` (rule, each attribute, instances, scoping, audit, the screen's hook, save-step end to end and the renewal pre-filling afterwards).


- **14 Oct 2026 (cc5 second walk): notice vs renewal.** A move-out notice and a renewal for the same lease cannot both stand: no renewal while a notice is on file, no notice while a renewal is in progress or signed (the agent withdraws one first); existing conflicts show a banner on the lease screen. The Next step offers "Continue in-inspection" for an in-inspection already begun. When a tenancy ends the property is relisted asking the last lease rent. See `rentals-faults-work-orders.md` 22.21.
