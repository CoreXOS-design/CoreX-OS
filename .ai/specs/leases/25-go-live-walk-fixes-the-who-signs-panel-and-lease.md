## Go-live walk fixes — the Who-signs panel and lease pre-fill (13 Oct 2026, cc2; cc5's full walk)

- **"Choose a property to see its landlord" with the property already chosen.** Reproduced in a real browser on QA1: opened from a property (`?property_id=`), the capture screen prints the property as plain text with a hidden id, but the form's own state (`propertyId`, `fixedPropertyId`) stayed empty, so the Who-signs lookup (`corex.leases.party-check`) was called WITHOUT a property: no landlord, no "needs ID or passport number — update contact" until the server's own check refused the press of "Create lease & prepare for signing". `fixedPropertyId` is now the preselected property, so the panel names what is missing, for which party, with the link to the contact, before anything is pressed.
- **Pre-fill everything CoreX already knows.** `LeaseSigningLauncher::propertySnapshot()` replaces the old title+suburb snapshot with what the e-sign wizard's own property step records (street line, unit, complex, suburb/town/city, erf, type, rent/deposit): the agreement's street address was the property's marketing TITLE and unit and complex were never filled. `LeaseSigningLauncher::addressFor()` gives each signing party the address CoreX knows: the contact's own; else built from the contact's street/suburb/city columns; else, for a tenant, the residential address on their rental application (the contact is usually blank — the applicant typed it into the application). The same rule backs the "needs address" check, so a tenant whose address is on file is no longer asked for it.
