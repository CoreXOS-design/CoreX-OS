# Buyers Report — what Johan will see

**One page, same shape as the Agency Performance & ROI report, in this order: problems first, then the numbers.**

---

## Top of the page — Needs Attention

The first thing Elize sees Monday morning is a list of buyers who need her to do something about them — not a wall of totals. Sorted worst-first, so the buyer who's been sitting the longest is at the top.

Each row shows: **buyer name · their agent · how long they've been stuck · why they're on the list.**

Three groups, stacked in this order:

1. **Cold and Lost buyers, longest-neglected first.** "Sarah Naidoo — 34 days since anyone worked her, currently Cold." A one-line reason where we have one (from the buyer's lost record, if lost).
2. **Buyers parked on purpose — shown separately, not mixed into the worry list.** If an agent deliberately moved a buyer to Cold themselves (not the system decaying them from silence), that's flagged with its own small marker — "Parked by [agent]" — so Elize doesn't chase someone who's genuinely on ice by choice, not neglect.
3. **Recently Lost, with the reason and what it cost.** A short list — buyer, agent, reason, and the pre-approval value that walked out the door — so a pattern (e.g. five buyers lost to "went with another agent" this month) is visible at a glance, not buried.

Click any name → opens the buyer's full picture: their wishlist(s), whether they've actually looked at the properties matched to them, every viewing/appointment, any feedback captured, and their full activity history. (This reuses the buyer detail screen that already exists in CoreX — we're not building a second one.)

---

## Below that — the numbers, same shape as the ROI report

**A period selector at the top** (This Month / Last Month / custom range, etc.) with the same "compare to previous period" toggle the ROI report has — every number can show "+12 vs last month" the same way commission does today.

**Stat tiles across the top of this section:**
- Buyers added
- Buyers Won (converted — bought through us)
- Buyers Lost (+ the total pre-approval value lost)
- Wishlists created
- Wishlist engagement — how many of the buyers with a wishlist have actually opened it and looked at what's matched
- Appointments held with buyers (viewings, etc.)
- Feedback captured from those appointments

**Click any tile number** → a pop-up window opens right there on the page (no navigating away) listing exactly who's behind that number — same as clicking "23 deals" on the ROI report opens a list of those 23 deals today.

**Below the tiles — the same per-agent table the ROI report has**, rolled up agent → branch → company, so every number reconciles the same way commission does. Each agent's row shows: buyers held, added, won, lost (+ value), appointments, feedback captured, average days-to-attention (how stale their book is on average).

**Click an agent's name or a branch name** → a full page for just that person or branch, same as clicking through to an agent's page on the ROI report today.

---

## The language

The system's own field for a buyer who's still warm calls this state **"warm"** internally — on this report, and everywhere Elize sees it, it's labelled **"Hot"**, because that's the word Johan uses and the word Elize will read. Same underlying data, Johan's word on screen.

---

## Who sees what

Same toggle the Buyer Pipeline board already has: **Mine / My Branch / Whole Agency**, defaulting sensibly by role (an agent defaults to their own; a branch manager like Elize defaults to her branch; an admin/owner defaults to the whole agency). Nobody can see another agency's data, ever — that's enforced the same way it is everywhere else in CoreX.

---

## What's new versus what already exists

Almost everything on this page reads from work that already exists — the buyer pipeline states, the wishlists, the activity log, the feedback captured from appointments. The one genuinely new piece: today CoreX can tell you a buyer *looked at* a matched property (they clicked it on their own link), but it can't yet tell you an agent *deliberately sent* them a specific match. We're adding that recording going forward — it starts building history from the day this ships, it just can't backdate before today.
